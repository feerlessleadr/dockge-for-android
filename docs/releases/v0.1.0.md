# Dockge for Android 0.1.0

First release. A personal Android app to manage dockge-enhanced instances from a phone. Sideload it (Obtainium or the APK below); there is no Play Store listing and no Google push.

## What is in it
- **Instances.** Save several dockge-enhanced servers. Live connection status, automatic reconnect, recovery after the phone sleeps or the network changes. Servers linked to an instance (federation) show up with their stacks.
- **Stacks and containers.** State, health, image, uptime and ports. Start, restart, stop, down and update for stacks; start, restart and stop for containers. Anything that stops or recreates asks first. A fixed-size progress screen shows the pull and recreate (or stop, start...) with a bar, and the full output is one tap away.
- **Updates.** Badges for stacks with a new image, the image digests and a link to the image page, and a confirmed one-tap update of a stack.
- **Alerts.** The app watches your servers itself and notifies you about new image updates, crash loops, unhealthy containers, failed backups and critical or high security findings. No notification server is needed. Generic text on the lock screen, a tap opens the instance or the stack.
- **Login.** User name, password and two-factor code. Only the session token is stored, encrypted with the Android Keystore.

## Requirements
- Android 8.0 or newer.
- An https address for each instance.
- The dockge-enhanced fork. Image updates need the image watcher switched on; crash, health, backup and security alerts need an administrator user.

## Known limits
- Not included: container logs, compose or environment editor, terminal.
- Alerts only cover the instance you added, not the servers linked to it, and nothing for cleanup reports, linked-server problems or Dockge's own updates (those exist only as Apprise or Discord messages).
- The progress bar is worked out from what compose prints. If a compose version prints something unexpected the bar can stay indeterminate; "Show full output" always works.
- Tested by the owner on one phone against one production and one test Dockge. Not yet exercised on a real server: a token that was revoked on the server, re-login after the server restarted, and the login rate limit.
